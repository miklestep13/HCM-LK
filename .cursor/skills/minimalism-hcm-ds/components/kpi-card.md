# KPI-карточка `.q-kpi` — когда брать и какую собрать

Читать, когда на экране нужна сводка показателей, ключевые атрибуты в шапке объекта или одна главная цифра.
Правила общие для любого продукта на этой ДС: CRM, банк, логистика, HR, сервис. Особенности Q.HCM — в §10, примеры
из прототипа Q.HCM — в §11. Стили — `assets/kpi-card.css`. Геометрия, свойства компонента и сборка в Figma —
`references/kpi-card-spec.md` (открывать для точного воспроизведения или работы в Figma).

## 1. Что это

Карточка показывает **одно значение**, которое человек должен понять за секунду, до того как пойдет в детали:
«сколько», «как идет», «успеваем ли», «что изменилось», «что не так».

- Это сводка, не рабочая область: в карточке нет списка, формы, кнопок и длинного текста.
- Значение — выжимка из данных того же экрана. Оно совпадает с таблицей, списком и другими экранами продукта.
- Пять типов (`Type`): Default, Progress, Trend, Arrow subtitle, Arrow inline. Четыре статуса (`Status`): Normal,
  Success, Warning, Critical. Направление (`Direction`: Up, Down, Unchanged) — только у двух Arrow.

## 2. Когда брать

Нужны **все** условия:

1. Есть ключевое значение: число, доля, сумма, срок, дата, период или короткий атрибут в одну строку.
2. Его нужно увидеть раньше деталей: над таблицей, в шапке объекта, в сводке виджета.
3. Оно должно выделяться. Второстепенное значение — строка «метка — значение» `.q-dl`.

| Количество | Когда |
|---|---|
| 1 | Одно главное значение виджета или колонки, на которое опирается остальное: итог над списком, главный показатель в узкой колонке, метрика над графиком |
| 2–4 | Несколько значений отвечают на один вопрос пользователя («как идут продажи за месяц», «в каком состоянии заказы») |
| 5 и больше | Не ставить. Взять 4 главных, остальное — `.q-dl` или таблица. Второго ряда нет |

| Место | Карточек | Что в них |
|---|---|---|
| Шапка объекта `.q-ohead` (договор, проект, заказ, план) | 2–4 | Ключевые атрибуты и числа объекта: сумма, срок, ответственный, этап |
| Сводка раздела — отдельный виджет над рабочим списком | 3–4 | Состояние процесса по всем объектам раздела: сколько всего, как идет, где проблемы |
| Сводка внутри виджета | 1–3 | Итог по одному объекту или срезу |
| Узкая колонка | 1–2 | Главное значение объекта |
| Карточка сущности (клиент, сотрудник, поставщик) | 3–4 | Счетчики сущности: сделки, обращения, стаж |
| Отчеты и аналитика | 1–4 | Главные метрики над графиками, с изменением к прошлому периоду |

## 3. Когда не брать

| Ситуация | Вместо |
|---|---|
| Больше 4 значений | `.q-dl` или таблица |
| Значение второстепенное | Строка «метка — значение» |
| Не помещается в 1–2 строки (описание, имя с должностью, список имен) | `.q-dl`, строка списка |
| Статус объекта («Утверждено», «Просрочен», «Оплачен») | Тег в шапке объекта |
| Прогресс самого объекта (сколько сделано по плану, проекту, курсу) | Полоса прогресса `.q-prg--l` (`references/progress-bar.md`) |
| Список людей, задач, позиций | Строки списка или таблица |
| Нужно действие | Кнопка в шапке страницы или на острове |
| Динамика с осями, несколько рядов, разбивка | График в виджете аналитики |
| Строка таблицы, карточка в списке | Не использовать: карточка — элемент сводки |

## 4. Какой Type

Проверять по порядку, первое подходящее правило решает. В карточке ровно один Type.

**1. Progress** — доля «сколько заполнено из целого». Все условия:
- доля 0–100% с базой «N из M», 100% — естественный предел;
- полоса показывает **ту же долю**, что Value (§9).

Пример: «Оплачено — 83%, 20 из 24 счетов». Не Progress: результат больше 100% (выполнение плана продаж 104%),
изменение в процентах, оценка по шкале («4,6 из 5»), среднее по набору долей («Средняя загрузка — 52%»).

**2. Arrow** — важно, насколько значение изменилось к прошлому периоду или плану, и изменение известно числом.

| Изменение | Direction | Символ | Trend value |
|---|---|---|---|
| Выросло, значимо | Up | ▲ цвета Status | Величина роста: «4 п. п.», «0,2», «12 000 ₽» |
| Снизилось, значимо | Down | ▼ цвета Status | Величина снижения без минуса: «3 п. п.», «2» |
| Нет изменения | Unchanged | «=» серый | «0%» |
| Есть, но в данных признано незначимым | Unchanged | «=» серый | Фактическое значение из данных: «0,3%», не «0%» |

- Период сравнения и порог значимости — только из задачи или данных, не придумывать. Порога нет — любое ненулевое
  изменение это Up или Down, Unchanged только при нуле.
- Trend value без «+» и «−»: направление показывает символ. Минус в тексте символ не разворачивает. Direction и
  Trend value ставятся вместе, по одному сравнению. Заглушку «0%» заменить, если изменение не нулевое.
- Единица: изменение доли — «п. п.»; относительное — «%»; количество и деньги — в единицах значения.
- Нет предыдущего значения, динамика неизвестна, ошибка, загрузка — **не Unchanged**, а Default с причиной в
  пояснении («Нет данных за прошлый месяц»).

| Type | Когда | Пример |
|---|---|---|
| Arrow inline | Изменение читается вместе с числом; пояснение занято базой или скрыто | «Оценка сервиса — 4,6 ▲0,2», «из 5 · 312 отзывов» |
| Arrow subtitle | Изменению нужна база рядом: «к чему» | «Конверсия — 18%», «▲2 п. п. к сентябрю» |

В Arrow subtitle нижняя строка остается без пояснения. Нечего написать после стрелки — Arrow inline.

**3. Trend** — есть ряд от 3 периодов и важна форма динамики. Ограничения компонента: линия статичная и всегда
растущая, Value и Subtitle не подключены к свойствам, пояснение не скрывается. Брать только для реально растущего ряда;
падает или стоит — Arrow с Down или Unchanged.

**4. Default** — все остальное: количества, сроки и остатки, даты, периоды, суммы, средние, атрибуты в шапке,
значения без известной базы сравнения.

**Ряд:**
- Карточки одной высоты. Исходные: Progress — 100, остальные — 90; без пояснения Default и Arrow inline — 70,
  Arrow subtitle остается 90.
- Progress с другими Type не смешивать: если полоса нужна одной из четырех, ряд без полос, база уходит в пояснение.
- Пояснение есть у всех карточек ряда или ни у одной.

## 5. Какой Status

Status — смысл для пользователя, а не цвет по числу. Задавать явно, по правилу предметной области. Не выводить из
величины, знака «%», Direction или линии. По умолчанию — Normal.

| Status | Акцент | Когда | Пример |
|---|---|---|---|
| Normal | `--q-card-text`, полоса `--q-progressbar-value-bg` | Нейтральный факт; ноль проблем; срок еще не наступил; рост без оценки | «Открытых сделок — 48», «Срок договора — 31.12.2026» |
| Warning | `--q-warning-700` | Нужно внимание, нарушения нет: отставание от плана, срок на исходе, ждут решения, давно без движения | «Без ответа больше суток — 3» |
| Critical | `--q-error-700` | **Только** просрочка, превышение лимита, нарушение, итоговый провал, риск потери | «Просроченные платежи — 6» |
| Success | `--q-success-700` | Норма полностью достигнута, и это стоит подсветить | «План месяца выполнен — 100%» |

- Акцентом красятся значение, полоса, линия графика, стрелка и число изменения. При Unchanged «=» и число всегда
  `--q-base-500`, а значение остается цвета Status. Фон, заголовок, пояснение и иконки статус не меняет.
- Direction и Status независимы: Up не значит Success, Down не значит Critical. Пример: просроченных платежей стало
  меньше, но они есть — Down + Critical; стало ноль — Down + Success; выросли расходы — Up + Warning.
- В ряду не больше 1–2 цветных карточек. Цветной статус всегда объясняется пояснением.
- Пороги предметной области (SLA, лимиты, шкалы оценки) брать как есть, не придумывать.
- Срок — Critical только после того, как прошел, и пока объект не завершен.

## 6. Тексты

- **Title** — что измеряем, 1–4 слова, без двоеточия, sentence case. Не повторять заголовок виджета; единица — в Value.
- **Value** — одна строка: «83%», «92 дня», «6 шт.», «52 000 ₽» (разряды через пробел, валюта после суммы); даты
  ДД.ММ.ГГГГ; периоды словами («III квартал 2026»); нет значения — «—» и причина в пояснении. Компонент ничего не
  считает и не форматирует. В Arrow inline длинное значение не переносится вместе со стрелкой — такое значение только
  в Default или Arrow subtitle.
- **Trend value** — только в Arrow: величина без знака, сходится с Value и Direction
  (78% при прошлом 74% — Up «4 п. п.»; при 81% — Down «3 п. п.»; при 78% — Unchanged «0%»).
- **Subtitle** — контекст: база («20 из 24 счетов»), сравнение («к сентябрю»), кто или что за числом
  («ООО „Альфа“ — 40% выручки»), что делать («Сначала просроченные»). До 2 строк. Обязательно у Progress, Trend и любого
  цветного статуса. Скрывать свойством, не пробелами.

## 7. Иконки и клик

- **Info** — только если у метрики неочевидная формула и текст подсказки известен. Иначе скрыть.
- **Меню** — только если есть действие с карточкой (выгрузить, открыть отчет). Иначе скрыть. В шапке объекта обычно
  скрыты обе.
- Переход к деталям — кликом по всей карточке (`a.q-kpi`, ховер — значение `--q-primary-500`), не через меню.
  В компоненте Figma клик и состояния не заданы — добавлять только по требованию экрана.

## 8. Раскладка

- Ряд `.q-kpis`: 1–4 карточки одной ширины, gap 12; < 1024 — 2 колонки. Одиночная — на ширину колонки, не уже 160.
- Сводка раздела — отдельным виджетом над рабочим. В шапке объекта — после описания.
- Порядок в ряду: **масштаб → ход → проблемы → срок** («Всего заказов → Доставлено вовремя → Просрочено → До закрытия
  месяца»).

## 9. Соответствие полосы и числа (Progress)

Агент **всегда** делает так, чтобы длина полосы совпадала с Value: 83% — полоса на 83% трека.
- Верстка: `--p` на `.q-kpi__bar` из того же числа, что Value.
- Figma: в экземпляре длина полосы зафиксирована на 78% и не меняется. Если Value не 78%, агент отвязывает копию
  карточки (`detachInstance`) и выставляет ширину `Fill` = ширина трека × доля; слой называет «KPI Card · отвязано».
  Подробно — `kpi-card-spec.md`, §6.

## 10. Особенности Q.HCM

- Данные экранов — из скилла `hcm-demo-legend`: люди, роли, даты (сегодня 30.09.2026), цифры совпадают между экранами.
- Периоды словами («III квартал 2026»), но у ИПР — кодом атрибута системы (4FQ2026).
- Рейтинг целей 0/70/85/110: итог «Ниже ожиданий» (< 70%) — Critical, отставание в процессе — Warning, итог
  «Превышает» (от 85%) — Success.
- Типовые места: шапка ИПР, плана адаптации, цели, бланка аттестации; сводки разделов «Управления персоналом» (Адаптация,
  Цели, ИПР сотрудников, Аттестация, Кадровый резерв); профиль сотрудника; «Аналитика персонала».
- Прогресс плана (ИПР, адаптация) — полоса шапки, не Progress-карточка.

## 12. Проверка

- [ ] Карточек 1–4; одиночная — только для главного значения; в ряду все отвечают на один вопрос.
- [ ] Не дублирует статус объекта и его прогресс.
- [ ] Type по §4: Progress — доля 0–100% с базой; Arrow — с известной базой, Direction по факту и заданному порогу,
      без данных — Default с причиной; Trend — только растущий ряд.
- [ ] Ряд одной высоты, Progress не смешан, пояснение у всех или ни у кого.
- [ ] Status задан по смыслу, не по Direction; цветных не больше двух, у каждой причина в пояснении; Critical — только
      просрочка, нарушение, итоговый провал, риск потери.
- [ ] Value в одну строку с единицей; **длина полосы равна Value** (§9); Trend value без знака, сходится с Value и
      Direction; «0%» заменен, если изменение не нулевое.
- [ ] Info и меню — только при наличии подсказки и действий.
- [ ] Цвета только токенами из `assets/kpi-card.css`, без hex.
- [ ] Числа совпадают с другими экранами продукта (в Q.HCM — с легендой).
