# Ячейка пользователя `User` `.q-user` — аватар, имя, подпись, теги

Читать, когда на экране человек с именем: строка участника, исполнитель в атрибутах, ячейка таблицы, виджет «Коллеги»,
карточка сотрудника, узел оргструктуры. Правила общие для любого продукта на этой ДС. Особенности Q.HCM — в §9,
примеры — в §10. Стили — `assets/user.css`. Компонент Figma и сборка — `references/user-spec.md`.
Аватар без текста и группа аватаров — `references/avatar.md`; объект с иконкой — `references/icon.md`.

## 1. Что это

Человек одной строкой или блоком: аватар → имя → подпись → теги. Подпись — должность, роль в процессе, подразделение
или мета (дата комментария). Теги — роль («Руководитель», «Наставник») или событие («Отпуск с 28.12», «В офисе»).

Ячейка не нажимается отдельно: переход — по строке, карточке или имени (ховер — имя `--q-primary-500`).

## 2. Вид: Layout × Size

| Layout · Size | Аватар | Отступ до текста | Где |
|---|---|---|---|
| **Row · S** | 32 | 8 | Ячейка таблицы, атрибут («Исполнитель», «Инициатор»), значение поля-выбора, 9-box, список целей |
| **Row · M** | 36 | 12 | Строка участника, участник бланка, комментарий, шапка опроса, благодарность; в шапке приложения — внутри области пользователя навигации (§6) |
| **Row · L** | 64 | 12 | Виджеты «Коллеги», «Команда», «Дни рождения» на главной |
| **Row · XL** | 112 | 12 | Карточка сотрудника `.q-ecard`: главная, профиль, каталог сотрудников, HR-карточка |
| **Stack · L** | 64 | 12 | Текст под аватаром, по центру: узел оргструктуры, карточка руководителя в «Руководстве» |

- Вид выбирают по месту, а не по важности человека. В одном списке, таблице, ряду карточек — один вид.
- Таблица — только S (в `Table / Cell` это `Type=Person`).
- Других размеров нет: 26, 28, 34, 40, 44 → S или M; 52, 88 → L; 120 → XL.

## 3. Что включается

| Свойство | По умолчанию | Когда включать |
|---|---|---|
| `Photo` | вкл. | Выключить, если фото нет: аватар `No photo` (`pi-user` на сером фоне) |
| `Show position` | вкл. | Выключить, если подпись не нужна: исполнитель в атрибутах, ячейка таблицы подбора |
| `Tag inline` | выкл. | Один тег в строке с именем: категория благодарности, роль в «Коллегах» |
| `Tags below` | выкл. | Теги отдельной строкой под подписью: роли участника бланка, статус в карточке сотрудника |
| `Tag 2` | выкл. | Второй тег в строке `Tags below` |

- Тег в строке с именем и строка тегов под подписью вместе не ставятся: выбирают одно место.
- Больше двух тегов не ставят — остальное в карточке или профиле.

## 4. Тексты и стили

| Элемент | Стиль | Цвет |
|---|---|---|
| Имя | 14/20 SemiBold (`ui-headline-4`), одна строка с «…» (в Stack — по центру) | `--q-content-text` |
| Подпись | 12/16 (`ui-description-1`), вплотную к имени (отступ 0), одна строка (в Stack — до двух) | `--q-base-500` |
| Тег | Бейдж `bage` (компонент Q.HCM-components) `size=hug`, высота 24 | по §5 |
| Строка тегов | Отступ 8 от подписи, между тегами 6 | — |

- ФИО: полностью — в карточке сотрудника и профиле; «Фамилия И. О.» — в таблицах, атрибутах, строках.
- Имя никогда не 16 и не 20: крупное имя в шапке — это шапка объекта (§7), не ячейка.

## 5. Цвет тега

| Тег | Состояние `bage` |
|---|---|
| В офисе | success |
| Руководитель, наставник, день рождения, новый сотрудник | Info |
| Отпуск, больничный | Default |
| Категория благодарности | Default |

Красный тег (Error) в ячейке пользователя не ставят: просрочка и риск относятся к объекту, а не к человеку.

## 6. Раскладка

- Row: аватар слева, текст справа, по центру по вертикали; ширина ячейки — по контейнеру, имя и подпись обрезаются «…».
- Stack: аватар сверху, под ним текст по центру; отступ 12; ширина — по карточке или узлу.
- Аватар и тег — только из компонентов `Avatar` и `bage`; размер аватара определяется `Size` и отдельно не меняется.
- В шапке приложения `User` Row M стоит внутри области пользователя навигации: справа шеврон 12, область кликается
  целиком и открывает меню («Профиль», «Язык», «Выйти из аккаунта»). Шеврон — часть навигации, не `User`.

## 7. Запреты

**Нельзя:**

1. Брать аватар, шрифт или отступ вне §2 и §4: имя 14/18 или 20/26, подпись 14/18, отступ 10.
2. Смешивать виды (`Size`, `Layout`) в одном списке, таблице или ряду карточек.
3. Делать крупную «ячейку» с именем 20/26 в шапке объекта — там ФИО в названии шапки через « · » (`SKILL.md`, 22.10.2026).
4. Ставить эмодзи или кружок-статус на аватар вместо тега («🌴» → тег «Отпуск с 28.12»).
5. Ставить теги высотой 17, 20, 22 или самодельные — только `bage` 24.
6. Ставить тег в строке с именем и строку тегов одновременно; больше двух тегов.
7. Красить подпись не в `--q-base-500` (`#4a4a4a`, `#7182ac`, черный).
8. Ставить чужое фото, инициалы или пустой квадрат — нет фото: `Photo` выкл.
9. Делать ячейку пользователя кнопкой — переход по строке, карточке или имени.

## 8. Проверка

- [ ] Вид по §2, один на список; в таблице — S.
- [ ] Имя 14/20 SemiBold, подпись 12/16 `base-500` вплотную.
- [ ] Теги — `bage` 24, цвет по §5, одно место (в строке или под подписью), не больше двух.
- [ ] Нет фото — `Photo` выкл., `pi-user`.
- [ ] Люди, должности, теги — из `hcm-demo-legend`.

## 9. Особенности Q.HCM

- Люди — только из `ORG` легенды; должность — как в легенде (Федорова — «Директор департамента розничного бизнеса»).
- Шапка приложения — вошедший: Павел Иванов в роли 1, Смирнова В. О. в роли 2. Это область пользователя компонента
  навигации (`Navigation`): `User` Row M + шеврон меню; отдельно `User` в шапку не ставят.
- «Коллеги» Павла: Федорова (тег «Руководитель»), Гусева, Крылов, Кузьмин, Лебедев (тег «Отпуск с 28.12»).
- В карточке сотрудника из «Управления персоналом» кадровые действия — в меню «…», не на ячейке.
