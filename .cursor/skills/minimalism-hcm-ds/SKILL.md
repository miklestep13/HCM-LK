# Minimalism_HCM

Источник правил — пакет от 01.11.2026. Цвета `--q-*`, типографика `ui-*` / `article-*`. Hex и сырые size/weight не писать.

## Что открывать

На один экран — только эти файлы, и только если деталь реально есть на экране:

1. `foundations.md` — один раз на экран.
2. `components/<имя>.md` — правила компонента.
3. `blocks/<имя>.md` — если экран собирается из блока.

Не открывать пачкой. Не открывать соседние компоненты «на всякий случай».

| Когда | Файл |
|---|---|
| Кнопка, ссылка-действие, иконочная | `components/button.md` |
| Бейдж | `components/badge.md` |
| Таблица | `components/table.md` |
| Аватар | `components/avatar.md` |
| Плитка с иконкой или картинкой | `components/icon.md` |
| KPI | `components/kpi-card.md` |
| Полоса прогресса | `components/progress-bar.md` |
| Ячейка человека | `components/user.md` |
| Шапка приложения | `components/navigation.md` |
| Виджет, остров, список, фильтры, шапка объекта, карточки | `blocks/screens.md` |

`figma/*.md` — только когда собираешь или правишь компонент в Figma. `assets/*.css` — не читать: подключить файл после `tokens.css` и пользоваться классами. В скилл CSS не копировать.

Внутри `components/` есть фразы «прочитай spec и css». Их пропускать: spec лежит в `figma/`, css — в `assets/`.

Демо-люди, цифры и роли — отдельный скилл `hcm-demo-legend`. Открывать его только когда наполняешь экран данными.

## Сборка

Компонент решает вид и состояния. Блок только перечисляет, какие компоненты внутрь и в каком порядке. Свойства компонента в блоке не повторять.

Порядок: каркас из `foundations.md` → блоки экрана → у каждого блока только нужные компоненты → классы из `assets/`, без ручного переписывания значений.
