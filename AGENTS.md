# Правила проекта hcm-ui для ИИ-ассистентов

Это прототип HR-платформы **Q.HCM** («Меридиан Банк») на Angular. С проектом работают дизайнеры через ИИ, поэтому правила ниже нужно соблюдать при любой правке.

## Как устроен проект

```
src/
  styles/                 глобальные стили
    _tokens.scss          токены Q.PALETTE (цвета light/dark), типографика Minimalism — менять только здесь
    _fonts.scss, fonts/   Open Sans
    _avatars.scss         портреты сотрудников (.av1–.av8, .av.ph41–…)
    _base.scss            сброс и база
    _ui.scss              общие атомы: .c/.ch/.cb (карточка), .btn, .bdg, .chip, .item, .seg, .stc, .kv, .bar, .clbg, раскладка .cols
    _controls.scss        контролы: заголовок страницы .pf-top, шапка с фильтрами .ftbar, поле поиска, селект .fsel, календарь, всплывающие списки .fpop, модальное окно .mdlo
  app/
    core/                 каркас приложения
      layout/header/      шапка и меню
      layout/dev-panel/   dev-панель «Демо» (переключатели демо-состояний)
      navigation/         меню (nav.config.ts), переходы (nav.service.ts), список перенесенных страниц (pages.ts)
      legacy/             мост к старому прототипу (страницы, которые еще не перенесены)
      demo/               демо-состояния (этап карты целей, роль в новостях) и демо-хранилища (лента новостей, цели — GoalsStore, обучение — LearnStore, ИПР — IprStore)
    shared/ui/            базовые компоненты без бизнес-логики:
                          card, badge, list-item, progress, stat-cell, kv-row, seg, icon, tooltip, toast,

                          select (valuePrefix — «Тип: МВО»), multi-select, chips, filter-input, date-range (период), date-field (дата),

                          plan-summary, news-post, events («Мероприятия» — карточка целиком: <div app-events [events]>), poll, employee-card, comm-cover, comments,
                          wallet-send (сайдбар «Перечислить валюту»: inject(WalletSendService).open(), стоит в app.html),
                          learn-action (кнопка действия с курсом / программой / мероприятием: [learn-action]),
                          ipr-task-card, ipr-comps (задачи и компетенции ИПР — страница ИПР и бланк аттестации),

    pages/                страницы; страница = компонент, собранный из блоков
      home/
        home.ts|html|scss       сборка страницы (порядок блоков, колонки)
        home-profile/ …         блоки этой страницы (каждый блок — своя папка)
```

## Правила

1. **Страница = компонент из блоков.** Каждый визуальный блок страницы (карточка, таблица, панель фильтров) — отдельный компонент в папке страницы: `pages/<страница>/<страница>-<блок>/`. Фильтры, модальные окна и сайдбары страницы — тоже отдельные компоненты рядом.
2. **Виджеты.** Если блок нужен на второй странице и логика с видом те же — переносим его в `widgets/<имя>/` и подключаем в обе страницы. Пример: `widgets/plan-summary` (шапка ИПР / карты целей). Каждый виджет показан на странице «Виджеты» (меню профиля, `pages/widgets`): новый виджет — добавить в каталог `WIDGETS` (`data/widgets.data.ts`) и живой пример в `pages/widgets/widgets.ts`.
3. **Базовые компоненты** (`shared/ui`) — без бизнес-логики и без данных. Новый атом интерфейса (поле, чекбокс, таблица) — сюда.
4. **Данные** — только в `data/*.data.ts`, типы — в `interface/`. В шаблонах не писать тексты-данные (ФИО, суммы, даты).
5. **Стили.**
   - Цвета и шрифты — только через токены: `color: var(--q-…)`, `font: var(--q-font-ui-…)`. Произвольные размеры шрифта и HEX-цвета не использовать.
   - Общие атомы — в `src/styles/_ui.scss`. Стили блока — в его `.scss`, все селекторы с префиксом класса блока (`.hm-learning .crs …`).
   - Блоки страниц и виджеты используют `encapsulation: ViewEncapsulation.None` и класс на хосте (`host: { class: 'hm-learning' }`) — так стили работают как обычный CSS прототипа.
   - Хост страницы всегда с классами `pg pg-<ключ>` (`host: { class: 'pg pg-news' }`): общие правила страниц прототипа написаны через `.pg` (например, отступы карточек на всех страницах, кроме главной и обзора компании).
   - Блок страницы может стоять прямо на элементе карточки: `<div class="c" company-events></div>` (селектор-атрибут `[company-events]`) — так сохраняется разметка `.c > .ch + .cb`, на которую опираются стили.
6. **Компоненты Angular:** standalone, `ChangeDetectionStrategy.OnPush`, `input()`/`output()`, signals (`signal`, `computed`), новый синтаксис шаблонов `@if`/`@for`. Файлы именуются как генерирует `ng generate component`: `name.ts`, `name.html`, `name.scss`.
7. **Шапка с фильтрами** — только `app-filter-bar`: строка 1 — поиск, кнопка фильтров, действия (`ftAction`); строка 2 — фильтры (`app-select`, `app-date-range`), скрыта по умолчанию. Сортировка — `<button ftAction app-sort-button>`. Подтверждение удаления — `ConfirmService.ask(...)`.
8. **Демо-состояния** (этапы процесса, роли, сценарии) — только через dev-панель: страница регистрирует переключатель в `DevPanelService.register(...)` в конструкторе и снимает его в `ngOnDestroy`. Общие состояния — в `core/demo/demo-state.service.ts`.
9. **Тексты интерфейса** — по-русски, в стиле прототипа (буква «е» вместо «ё», кавычки «ёлочки»).
10. **Таблицы.** Действия строки (кнопка «⋯», иконки) — всегда последняя колонка справа: `<th class="tact">` / `<td class="tact">`. Она закреплена справа и видна даже при горизонтальной прокрутке таблицы (обертка `.tw` с `overflow-x: auto`). Чек-бокс и стрелка аккордеона — первая колонка слева, не закрепляются. Если в строках есть чек-боксы, чек-бокс есть и в заголовке таблицы — «Выбрать все» записи на странице (с промежуточным состоянием). Кнопки настройки столбцов в таблицах не ставим.
11. **Формы-страницы** (не сайдбар и не модальное окно) — без кнопки «Отменить»: только основное действие («Сохранить», «Создать»). В сайдбарах и модальных окнах «Отменить» остается.
12. **Счетчики в табах** — `<span class="pntc">N</span>` сразу после названия вкладки (стиль в `_ui.scss`: голубая плашка `--blue-bg`, синее число `--blue`, 12px, скругление 6px; одинаково на активной и неактивной вкладке). `.chip` в табах не используем.
13. **Сортировка** — только иконка ⇅, без стрелки-шеврона (`app-sort-button`).
14. **Кнопки-иконки панели фильтров** (фильтр, сортировка, переключатель вида «Карточки / Таблица» `app-view-switch`) — на голубом фоне `--raised` (`--blue-bg`), серый фон не используем.
15. **Прогресс объекта** (курс, программа, бланк аттестации, ИПР, оценка) — цвет по статусу: выполняется — желтый (`tone=''`/`'warn'`), просрочен — красный (`'dg'`), выполнен или 100 % — зеленый (`'ok'`). `app-progress` выбирает цвет сам по `tone` и `percent`.
16. **Кнопки объекта** (страница или карточка, которую можно изменить или удалить) — справа от заголовка две кнопки: «Удалить» слева — красная `btn dng` (бледный фон `--q-error-50`, текст `--q-error-500`, наведение — `--q-error-100`), «Редактировать» правее — голубая `btn raised` (голубой фон `--blue-bg`, синий текст). Обертка `<span class="objacts">` (стиль в `_ui.scss`). Если удалить нельзя — только «Редактировать». В карточке сетки (мероприятие, сообщество в списке) кнопки внизу карточки на всю ширину, друг под другом: сверху «Редактировать», под ней «Удалить». Иконки-карандаши вместо этих кнопок не используем.
17. **Скрываемый блок** (сворачивается по клику на шапку) — стрелка-шеврон **слева** от заголовка: `▾ Заголовок`, открыт — стрелка вниз, свернут — вправо. В свернутом виде заголовок посередине карточки: отступ сверху и снизу одинаковый (`.c > .ch:last-child` в `_ui.scss`: 20 на главной, 24 на остальных страницах).

## Перенос страницы из старого прототипа

1. Найти страницу в `public/legacy/index.html` (`<div id="pg-<ключ>">`) и ее JS-функции.
2. Создать `pages/<ключ>/` с компонентом страницы и блоками; данные — в `data/`, модели — в `interface/`.
3. Добавить маршрут в `app/app.routes.ts` и ключ в `core/navigation/pages.ts` — с этого момента меню и переходы из старого прототипа открывают Angular-страницу.
   Переход на еще не перенесенную страницу с параметром — `nav.go('newscard', { news: 'n1' })`; как прототип открывает такую страницу, описано в `OPEN` скрипта моста в конце `public/legacy/index.html`.
   Если страница прототипа меняет данные, которые уже живут в Angular (например, цели карты), — общие данные: хранилище регистрирует их в `LegacyService.share(ключ, { get, set })`,
   а мост — в `STATE_IN` / `STATE_OUT` (см. `core/demo/goals-store.service.ts`, `core/demo/learn-store.service.ts`): данные уходят в прототип при каждом переходе и возвращаются при возврате в Angular.
   Пункт меню с параметрами (`attrs`, например «Обучение»: `{ lt: 'cat' }`) открывает Angular-страницу с ними в адресе (`/dev?lt=cat`); страница читает их через `input()` (withComponentInputBinding).
4. Сверить вид со старой страницей (`#/legacy/<ключ>`) — должно совпадать.

## Команды

- `npm install` — один раз после скачивания
- `npm start` — запуск на http://localhost:4200 (обновляется при сохранении)
- `npm run build` — сборка в `dist/hcm-ui/browser` (статичные файлы, открываются без сервера через любой хостинг)
- `npm run deploy` — собрать и обновить публичную ссылку https://q-hcm-prototype.vercel.app (Vercel, проект `q-hcm-prototype`; нужен вход: `vercel login`)
